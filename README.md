# NodeSeek 用户 AI 画像

一个面向 [NodeSeek](https://www.nodeseek.com/) 的 Tampermonkey / Userscript 插件。

它的目标不是再告诉你一句“这个用户喜欢 VPS、服务器和网络线路”，而是尽量在几秒钟内回答更有价值的问题：

> **这是一个什么样的 NodeSeek 账号？最近主要在干什么？如果我要和他交易，公开历史里有哪些值得放心或需要留意的地方？**

当前版本：**v2.6.0**

## ✨ 功能概览

### 🧭 快速用户画像

点击用户名旁边的 **「AI 画像」**，脚本会先读取账号公开硬信息：

- NodeSeek 等级
- 加入天数
- 鸡腿
- 星辰
- 总主题数
- 总回复数

随后结合近期公开发帖与回复生成：

- 一句话画像
- 近期活动重心
- 值得留意的行为
- 简要交易速览

提示词会主动做“NodeSeek 基线过滤”：

像下面这些对大量 NodeSeek 用户都成立的话，不应该成为核心画像：

- 喜欢 VPS
- 关注服务器
- 讨论网络线路
- 参与二手交易
- 对 Linux 感兴趣

脚本更希望继续往下找：

- 偏好的地区 / 线路 / 商家
- 更像收机还是出机
- 是否经常买后测试、留档
- 是否有长期稳定的具体偏好
- 近期行为是否突然发生变化
- 有没有相对普通 NodeSeek 用户更有辨识度的模式

AI 可以有观点、可以稍微有点人味，但不会为了“锐评”强行毒舌或刻意冒犯。

## 🔍 可直接进入深度交易分析

v2.6 起，不需要先生成快速画像。

用户名旁的菜单可以直接选择：

- 🧭 快速画像
- 🔍 直接深度交易分析
- ⚖️ 管理记录

如果你本来就是因为准备交易才点开这个用户，可以直接跳过快速画像，减少等待和不必要的模型调用。

## 💰 深度交易分析

深度模式会扩大公开历史采样范围，并重点读取交易相关上下文，例如：

- 更长时间范围的主题 / 回复
- 交易相关主题
- 求购 / 出售 / 已收 / 已出
- 交易帖正文和上下文
- 买后测试与后续反馈
- 求购 → 收到 → 测试 → 转出等行为链
- 第三方公开回复
- 管理记录
- 正向公开信号
- 风险点
- 当前公开数据无法确认的内容

### 关于「已收 / 已出」

NodeSeek 中，将：

```text
【收】→【已收】
【出】→【已出】
```

作为交易状态更新是非常正常的行为。

因此本项目不会预设：

> “没有第三方公开回复确认，所以这笔交易可核验性低。”

在没有相反证据的情况下，用户自己正常更新的公开交易状态会按正常论坛记录处理。

如果评论区出现：

- 我要了
- 楼下止步
- 已收到
- 交易愉快

等内容，可以作为额外佐证，但不是每笔交易必须存在的“证明材料”。

### 不是「诈骗概率计算器」

脚本不会给出类似：

> 诈骗概率 27.6%

这种没有统计基础的假精确结果。

深度报告的作用是：

> 把公开历史里值得看的信号尽量整理出来，让你少翻几十页帖子。

最终交易判断仍然属于用户自己。

## ⚡ v2.6 多用户并发

这是 v2.6 相比 v2.5 很重要的一次底层调整。

以前如果：

1. 点用户 A 的画像；
2. A 还没返回；
3. 马上又点用户 B；

单一全局状态可能导致不同用户的异步请求互相影响。

v2.6 改成了 **按 UID 独立任务状态**：

```text
用户 A
├─ 快速画像任务
├─ 深度交易任务
├─ 进度
└─ 结果

用户 B
├─ 快速画像任务
├─ 深度交易任务
├─ 进度
└─ 结果
```

因此现在可以：

- A 还在分析时继续点 B
- A / B 在后台分别运行
- 切回 A 继续看 A 的进度
- A 完成后不会覆盖正在查看的 B
- 单独终止 A，不影响 B
- 后台用户完成后给出轻量完成提示

如果你不太在意 Token 消耗，甚至可以连续查看多个用户。

## ■ 可终止查询

快速画像或深度交易分析进行中，可以点击：

**■ 终止查询**

终止前会二次确认。

脚本会尝试停止：

- 尚未完成的 `fetch`
- `GM_xmlhttpRequest`
- 后续交易帖读取
- 后续模型请求
- 对应等待计时器

需要注意：

> 如果请求已经发送到 AI 服务商，终止本地等待并不代表服务商一定没有产生 Token 消耗。

所以界面会明确提醒这一点。

---

## ✓ 已查询用户状态

同一页面里，如果某个用户已经查询过：

- 默认：紫色 `AI画像`
- 正在分析：琥珀色 `⏳ AI画像`
- 已有结果 / 缓存：蓝色 `✓ AI画像`

同一个 UID 在不同楼层出现时会同步状态。

这个颜色只代表：

> **你已经查过这个账号。**

不代表脚本认为该账号“安全”或“可信”。

---

## ↻ 重新生成需要确认

为了避免误触：

- 重新生成快速画像
- 重新深挖交易报告

都会先弹出确认。

因为重新生成意味着绕过已有结果 / 缓存，再次调用模型并产生新的 Token 消耗。

## ⚖️ 管理记录

支持查询用户公开管理记录，并默认纳入深度交易分析。

管理记录查询来自第三方服务，并不是 NodeSeek 官方公开 API。

首次实际查询前，脚本会明确说明会发送的信息。

查询失败、超时、限流或第三方服务不可达时：

> 只跳过管理记录这个数据源，不会导致整个用户画像或深度交易分析失败。

同时：

- 普通水贴处罚不会自动等同于交易风险
- 普通版规处罚不会自动等同于交易风险
- 管理记录只有在具体内容确实和交易风险相关时才允许影响报告判断

### 管理记录时区

管理记录展示兼容社区后续提出的时区修正方案。

接口原始数据不会被修改。

只在显示 `actions_text` 时，将其中类似：

```text
8/12/2026, 7:49:34 AM
```

的 UTC 美式时间转换为北京时间显示。

### 深度报告内联展开

深度交易报告中，管理记录支持：

- 展开
- 收起

如果分享图片时管理记录处于展开状态，截图会包含展开后的记录。

如果处于收起状态，则只保留摘要。

## 🤖 多 AI Provider

配置界面支持独立保存三套 AI 服务：

### DeepSeek 官方

默认示例：

```text
API URL: https://api.deepseek.com/chat/completions
Model: deepseek-v4-flash
```

### OpenAI 官方

默认示例：

```text
API URL: https://api.openai.com/v1/chat/completions
Model: gpt-5.6
```

### 第三方 OpenAI-Compatible

可以自行配置：

- API Key
- API URL
- Model
- 快速画像 reasoning
- 深度交易 reasoning

不同 Provider 的 API Key / URL / Model 独立保存在 Tampermonkey 本地存储中。

因此可以：

```text
DeepSeek
→ 第三方 GPT
→ OpenAI
→ 再切回 DeepSeek
```

而不需要反复重新粘贴 API Key。

## 📊 Token 使用透明展示

普通画像和深度报告都会尽量展示供应商返回的：

- 输入 Token
- 输出 Token
- 总 Token
- Prompt Cache 命中
- Prompt Cache 未命中
- 缓存写入 Token（供应商支持时）
- Reasoning Token（供应商支持时）

如果命中脚本自己的本地结果缓存，会明确显示：

> 本地结果缓存命中，本次未重新调用模型。

避免用户误以为每次重新打开画像都会重新烧 Token。

# 📈 项目是怎么一步步变成现在这样的

这个项目并不是一开始就有现在这么多功能。

我最开始关注的是 NodeSeek 社区里“AI 用户画像”这个思路，实际使用之后逐渐发现：

> **AI 能总结，不代表总结出来的信息真的有用。**

最初的痛点之一，就是几乎所有 NodeSeek 用户最后都会得到：

> “关注 VPS / 服务器 / 网络线路。”

这当然可能是对的，但在 NodeSeek 里几乎等于没说。

因此后面的迭代逐渐从：

> **让 AI 总结更多**

变成：

> **让 AI 少说废话、找更有辨识度的东西，同时把硬数据和交易上下文补齐。**

## v2.1 — 先解决等待和深度报告可靠性

- 调整等待提示切换节奏
- 丰富 WAIT_HINTS
- 修复深度交易高推理模式下可能只消耗 reasoning budget、最终 `content` 为空的问题
- 增加输出预算和自动重试

## v2.2 — Token 透明化 + OpenAI-Compatible

- 展示输入 / 输出 / 总 Token
- 展示 Prompt Cache / Reasoning Token
- 增加 OpenAI 官方和第三方 OpenAI-Compatible 示例
- 修正交易分析中“已收 / 已出必须有第三方确认”的错误前提

## v2.3 — 从改源码配置变成图形化配置

- DeepSeek / OpenAI / 第三方 OAI 分别保存配置
- 切换 Provider 不再覆盖另一套 Key
- API URL / Model / reasoning 都可以在界面配置
- API Key 从硬编码转为 Tampermonkey 本地存储

## v2.4 — 管理记录进入交易分析

- 增加模型连接测试
- 默认在深度交易时查询管理记录
- 第一次调用第三方 API 前明确告知
- 管理记录接口失败不影响主分析
- 接入北京时间显示修正
- 面板支持调整大小

## v2.5 — 从分析面板变成真正能长期用的浮窗

- 标题栏拖拽移动
- 📌 钉住窗口
- 图片复制
- PNG 保存
- 完整结果截图
- 16 图床上传 / Markdown
- 图床 Auth-Token 与上传历史管理
- 第三方服务致谢

## v2.6 — 多用户并发与任务生命周期重构

- 多用户请求真正按 UID 隔离
- A / B 用户可以同时分析，不再串结果
- 可以直接跳过快速画像进入深度交易分析
- 查询中支持主动终止
- 已查用户按钮状态区分
- 重新生成加入确认
- 分享按钮统一使用 🖼️ 图标
- 管理记录改为深度报告内联折叠
- 展开管理记录时，分享截图会包含对应内容

# 🔐 隐私与第三方服务

## AI API Key

Key 通过 `GM_setValue` 保存在 Tampermonkey 脚本本地存储中。

调用模型时：

- DeepSeek Key 会发送给 DeepSeek API
- OpenAI Key 会发送给 OpenAI API
- 第三方 OAI Key 会发送给你自行配置的第三方 API

Key 不会因为普通浏览 NodeSeek 页面而自动发送给 NodeSeek。

## 管理记录查询

管理记录使用第三方查询服务：

```text
https://api.xxboxx.de
```

首次查询前脚本会说明：

可能发送：

- 目标用户名
- 当前登录 NodeSeek 用户名
- 当前登录 NodeSeek UID

用于查询与限流。

## 16 图床

图片上传使用：

```text
https://i.111666.best
```

上传意味着分享图片会存储到第三方图床服务器。

Auth-Token 用于上传和之后删除相应图片。

# ⚠️ 交易分析免责声明

本项目分析的是 NodeSeek 上可以看到的公开账号历史。

它不是：

- 实名认证系统
- NodeSeek 官方信用评分
- 交易担保
- 诈骗检测器
- 现实身份验证工具

请记住：

- 老号不代表绝对安全
- Lv1 不代表一定危险
- 高等级不是信用担保
- 没看到负面记录不代表风险为零
- AI 可能理解错误
- 第三方接口可能返回错误或不完整数据

涉及较大金额时，请遵守 NodeSeek 规则，并结合中介、账号历史、交易上下文和自己的判断。
