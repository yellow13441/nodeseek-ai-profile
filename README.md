# NodeSeek 用户 AI 画像

一个面向 [NodeSeek](https://www.nodeseek.com/) 的 Tampermonkey / Userscript 插件。它会整理账号公开资料、主题与评论，并调用你自己配置的 AI API，生成快速用户画像或更完整的深度交易分析。

> 它不是“诈骗概率计算器”，也不是 NodeSeek 官方信用评分。它做的是把分散在公开历史中的线索整理出来，帮助你少翻几十页帖子。

当前版本：**v2.8.0**

## 🧭 快速用户画像

点击用户名旁边的 **「AI画像」**，脚本会先读取以下公开硬信息：

- NodeSeek 等级
- 加入天数
- 鸡腿
- 星辰
- 总主题数
- 总回复数

随后按“分析模式”中的配置抽取公开主题与评论，生成：

- 一句话画像

- 值得留意的行为
- 具体标签
- 简要交易速览
- 独立的公开管理记录栏目（默认查询，可关闭）

生成过程中会持续显示采样数量、采样策略、低信息回复过滤、模型等待时间和可终止入口。

### NodeSeek 基线过滤

以下描述对大量 NodeSeek 用户都成立，不应自动成为画像核心：

- 喜欢 VPS
- 关注服务器
- 讨论网络线路
- 参与二手交易
- 对 Linux 感兴趣

脚本会继续寻找更有辨识度的公开模式，例如偏好的地区、线路或商家，更像收机还是出机，是否经常买后测试和留档，以及近期行为是否出现明显变化。

AI 可以有观点，也可以稍微有点人味，但不会为了“锐评”强行毒舌或刻意冒犯。

### 语境核验与 v2.8 一句话画像

单条评论很容易脱离上下文。从 v2.7 起，脚本可以在模型准备写入负面、异常、推广或交易风险类判断时，按配置补充：

- 主题标题
- 首帖正文
- 目标评论
- 引用文本
- 附近楼层

快速画像支持关闭、智能或严格核验；深度交易中的风险语境核验始终保留。若二次语境复核失败或返回结构不完整，脚本会保留第一次生成的完整结果，不会让一份有效画像被“样本不足”的占位结果覆盖。

v2.8 进一步要求一句话画像同时优先压缩“账号阶段 / 活动结构反差”“反复出现的具体对象或行为”与谨慎推断，并输出可校验的证据编号。新号、零主题或高评论量本身不会被直接推导为“小号”或“刷等级”。

## 🔍 深度交易分析

用户名旁的下拉菜单可以直接选择：

- `🧭 快速画像`
- `🔍 直接深度交易分析`
- `⚖️ 管理记录`
- `⚙️ 插件设置`

因此，如果你本来就是为了交易前查看账号，可以跳过快速画像，直接进入深度分析。

如果某个用户只有深度交易结果、还没有快速画像，再点击主按钮会优先打开已有深度报告；只有明确选择“快速画像”时才开始新的画像请求。

深度模式会扩大公开历史采样，并重点整理：

- 更长时间范围的主题与回复
- 求购、出售、已收、已出等交易主题
- 交易帖正文和上下文
- 买后测试与后续反馈
- 求购 → 收到 → 测试 → 转出等公开行为链
- 第三方公开回复
- 管理记录
- 正向公开信号、风险点与无法确认的内容

### 关于「已收 / 已出」

NodeSeek 中将：

```text
【收】→【已收】
【出】→【已出】
```

作为交易状态更新是正常行为。在没有相反证据时，用户自己更新的公开交易状态会被视为论坛历史的一部分。

评论区里的“我要了”“楼下止步”“已收到”“交易愉快”等内容可以作为额外佐证，但不会被设定为每笔交易必须存在的证明材料。脚本不会因为缺少第三方公开回复，就自动认定交易完成度低或可信度不足。

## 📊 v2.8 分析模式

快速画像与深度交易分析现在分别保存自己的数据预算。可配置项包括：

- 历史采样策略
- 主题与评论扫描页数
- 送入 AI 的主题与评论上限
- 同一主题评论上限
- 单条评论字符上限
- 语境核验数量
- 深度交易候选主题、每帖读取页数与第三方回复上限
- 是否在快速 / 自定义画像中自动包含管理记录（默认开启）
- 是否在深度分析中自动包含管理记录（默认开启）

支持四种历史采样策略：

| 策略 | 适用场景 |
| --- | --- |
| 最近活动 | 优先观察近期状态，快速画像默认使用 |
| 全历史均匀抽样 | 在账号可见历史范围内均匀取样 |
| 随机抽样 | 用随机页面降低固定位置偏差 |
| 近期 + 历史均匀覆盖 | 兼顾当前状态与历史跨度，深度分析默认使用 |

设置页会根据请求数量和模型输入规模显示轻量、中等或高负载提示，也可以一键恢复推荐默认值。抓取更多并不必然更准确，但通常会增加 NodeSeek 请求、等待时间和 Token 消耗。

管理记录不会被拿来凑行为画像的最低样本数。即使有效主题与评论不足、模型因此被跳过，查询到的管理记录仍会在结果中独立展示；错误、限流、关闭或用户取消也会明确标注，不会伪装成“没有记录”。

## 🤖 多 AI Provider

配置界面支持独立保存三套 AI 服务：

### DeepSeek 官方

```text
API URL: https://api.deepseek.com/chat/completions
Model: deepseek-v4-flash
```

### OpenAI 官方

```text
API URL: https://api.openai.com/v1/chat/completions
Model: gpt-5.6
```

[OpenAI 官方 GPT-5.6 模型指南](https://developers.openai.com/api/docs/guides/latest-model)说明，`gpt-5.6` 别名会路由到 `gpt-5.6-sol`；因此官方配置保留简洁别名，第三方兼容服务的新默认值则使用更容易被直接识别的完整模型名。

### 第三方 OpenAI-Compatible

新安装默认模型为：

```text
gpt-5.6-sol
```

可以自行配置 API Key、API URL、Model，以及快速画像和深度交易各自的 reasoning 等级。旧版本已经保存的 `gpt-5.6` 或其他模型名会原样保留，不会被迁移强制覆盖。

Model 改为“常用模型下拉 + 其他（手动输入）”：

- DeepSeek：`deepseek-v4-flash`、`deepseek-v4-pro`
- OpenAI / 第三方 OAI：`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.6`、`gpt-5.5`
- 供应商支持的任何其他模型仍可手动填写

三套 Provider 的配置分别保存在 Tampermonkey 本地，来回切换时不需要反复粘贴 Key。

### 模型连接测试

“测试连接”使用当前表单内容，无需先保存。它会发送一次很短的请求，因此会产生少量 Token 消耗。

测试结果会直接显示在当前 Provider 的测试按钮下方。成功时会展示模型、请求耗时和 Token；第三方 OpenAI-Compatible 如果需要兼容参数降级，也会明确标注“兼容模式”，并在当前会话记住该 URL + Model 的能力，后续请求直接使用兼容参数。

官方 Provider 的短测试超时为 30 秒，第三方 OAI 为 60 秒。短测试只用于验证接口与参数，不能代表长上下文、高 reasoning 的实际速度。

## ⚡ 多用户并发与任务控制

脚本按 UID 独立维护每个用户的快速画像、深度任务、进度、结果和终止句柄：

```text
用户 A
├─ 快速画像任务
├─ 深度交易任务
├─ 进度
└─ 结果

用户 B
├─ 快速画像任务
├─ 深度交易任务
├─ 进度
└─ 结果
```

因此可以在 A 分析期间继续查看 B，切回 A 查看进度，或只终止其中一个用户的任务。后台任务完成后会给出轻量提示，不会覆盖当前正在查看的其他用户。

### 临时任务窗口与刷新恢复

开始新的快速画像或深度交易分析时，脚本会在用户点击按钮的同时打开一个小型临时任务窗口。这个窗口是所有画像任务共用的长请求宿主：

- 同一时间只保留一个命名任务窗口，新任务不会把正在运行的窗口重新加载
- 一个窗口可以继续承接多个 UID 的快速画像和深度交易任务
- 原 NodeSeek 页面可以刷新、提交回复、跳转或关闭；模型请求和后续语境核验继续运行
- 刷新后的页面会重新连接已有任务，恢复按钮状态、当前进度、终止入口和最终结果
- 任务进度、取消请求和结果缓存通过 Tampermonkey 本地存储同步，不会发送给 NodeSeek
- 全部任务结束后，小窗口会短暂停留并自动关闭

任务运行期间请不要手动关闭这个小窗口；关闭浏览器本身同样会中断仍在进行的请求。为避免供应商已经生成却被重复计费，中断后的任务不会自动重新发送模型请求。

复用窗口接收第二个及后续任务时，会同时使用带 UID 的 Tampermonkey 持久信号和同源窗口消息主动唤醒，并保留 500ms 轮询兜底。尚未被窗口接收的排队任务可以立即终止，不会停在“正在终止查询”；30 秒仍未被接收时会结束为可重试错误，并明确说明尚未调用模型。

脚本会在用户点击事件中立即创建窗口，以降低浏览器弹窗拦截概率。如果浏览器仍然拦截，脚本不会弹出阻断式警告，而是退回当前页面继续生成，并在画像面板内说明本次刷新仍会中断。可以在浏览器地址栏的弹窗图标中允许 `www.nodeseek.com`，让后续任务稳定使用临时窗口。

### 终止查询

快速画像或深度分析进行中可以点击 **「■ 终止查询」**。确认后，脚本会尝试停止尚未完成的 fetch、`GM_xmlhttpRequest`、后续页面读取、模型请求和等待计时器。

> 请求一旦发到 AI 服务商，本地终止等待并不代表服务商一定没有产生 Token 消耗。

### 已查询状态与重新生成

- 默认：紫色 `AI画像`
- 正在分析：琥珀色 `⏳ AI画像`
- 已有结果或缓存：蓝色 `✓ AI画像`

状态只表示“你已经查过这个账号”，不代表脚本认为它安全或可信。重新生成快速画像或重新深挖都会二次确认，避免误触产生新的 Token。

## ⚖️ 管理记录

脚本支持查询用户公开管理记录，并默认纳入快速画像、自定义画像与深度交易分析。数据来自第三方服务，不是 NodeSeek 官方公开 API。

首次实际查询前会说明将发送的信息；查询失败、超时、限流或第三方服务不可达时，只会跳过这个数据源，不会让画像或深度分析整体失败。

同时遵循以下规则：

- 普通水贴或一般版规处罚不会自动等同交易风险
- 只有与交易风险确实相关的具体内容才允许影响报告判断
- 原始接口数据不被修改
- 展示 `actions_text` 时，可把 UTC 美式时间转换为北京时间
- 快速 / 自定义画像中也会独立、确定性展示查询状态与记录详情
- 深度报告中可以内联展开或收起管理记录
- 分享图片会跟随当前展开状态

## 📊 Token、耗时与缓存

快速画像和深度报告会尽量展示供应商返回的：

- 输入、输出与总 Token
- Prompt Cache 命中与未命中
- 缓存写入 Token（供应商支持时）
- Reasoning Token（供应商支持时）
- 模型请求次数
- 总耗时与模型等待时间
- 首个成功请求的可观测响应时间（浏览器 / Userscript API 能提供时）
- 单次模型阶段超过两分钟时的“本次较慢”提示

### 三种模式的输出预算

`最大输出 Token` 指输出 / completion 上限，也包含模型可能消耗的 reasoning Token，不是“输入 + 输出总量”。输入量主要由分析模式里的采样页数、条数与字符上限控制。

| 模式 | v2.8 默认最大输出 Token |
| --- | ---: |
| 快速画像 | 12,000 |
| 自定义画像 | 16,000 |
| 深度交易分析 | 32,000 |

每个 AI Provider 都可以独立把三项设置在 2,000–65,536 之间。若模型明确以 `finish_reason=length` 截断或只返回 reasoning，脚本最多扩容重试一次；网络错误和超时不会自动重试，以免供应商已经生成却因本地超时导致重复计费。

请求超时也按三种模式独立配置（30–900 秒）。第三方 OAI 默认分别为 300 / 360 / 600 秒，适合首个响应较慢的长上下文和高思考模型；DeepSeek 与 OpenAI 官方默认分别为 180 / 240 / 360 秒。

如果命中脚本本地结果缓存，会明确显示“本次未调用模型”，并保留上次生成时的 API 用量和原始耗时，避免把重新打开缓存误解为又消耗了一次 Token。

不同 Provider、Model、reasoning、采样设置和 Prompt 预设使用不同缓存签名；影响分析结果的配置变化不会错误复用旧结果。

v2.8 的结果缓存同时写入 Tampermonkey 本地存储，使临时任务窗口生成的结果可以被刷新后的 NodeSeek 页面读取。缓存有效期仍为 30 分钟，并自动清理过期及超出容量上限的记录。

- 复制图片到剪贴板

- 选择图床并上传、复制 Markdown

<p align="center">

</p>

分享图片会按“当前画像窗口宽度 + 完整内容高度”重新渲染，而不是只截取当前滚动区域，并自动移除操作按钮、设置按钮、查询进度、滚动条和 resize 手柄。

同一个分享窗口内，PNG 只生成一次。上传失败后可以直接手动重试或切换图床；脚本不会因超时自动改用下一家，因为“本地超时”并不能证明第一家没有成功，自动切换可能产生多个公开副本。

图床选择支持两种模式：固定默认图床，或在所有“已经填写凭据”的 Provider 间均衡随机轮换。轮换采用打乱后的循环池，每轮每家最多出现一次，并尽量避免连续两次选中同一家；匿名 Catbox 不会自动进入轮换池。分享窗口打开后，本次 Provider 即固定，重试不会偷偷切换；用户仍可在上传前手动改选，且不会因此改写默认设置。

分享窗口会显示一条非阻断的“友善分享提示”：画像虽然整理自公开论坛信息，但不同用户对被集中展示和再次传播的接受程度不同。分享仍然是插件传播和社区体验的重要方式；如果被画像者明确表示不希望继续公开，建议及时移除帖子中的图片，并根据上传历史所示能力删除图床远端副本。脚本不会为此增加强制确认框。

## ☁️ 多图床 Provider

所有图床都是可选功能，所需凭据必须由用户自行申请；项目不提供或内置开发者 Key。

| 图床 | 配置 | 删除能力 |
| --- | --- | --- |
| 16 图床 | 任意 Auth-Token | 使用同一 Token 调用 API 删除 |
| [NodeImage](https://www.nodeimage.com/) | NodeSeek 登录后申请 API Key；额度以其当前等级规则为准 | 有图片 ID 时调用 API 删除 |
| [ImgBB](https://api.imgbb.com/) | 自行申请 API Key，可选自动过期时间 | 官方返回删除网页，插件只负责打开 |
| [FreeImage.host](https://freeimage.host/api) | 自行申请 API Key | 官方 API 未承诺插件内删除 |
| [Catbox](https://catbox.moe/tools.php) | User Hash 可选 | 匿名上传不能删；绑定 User Hash 后可请求删除 |

统一支持：

- 固定默认 Provider，或在已配置凭据的 Provider 间均衡随机轮换
- 在分享窗口中查看本次选择并手动改选
- 上传图片并自动复制 Markdown
- 保存最近上传记录
- 打开图片、复制 Markdown
- 按服务真实能力显示“远端删除 / 删除页 / 仅删本地”
- 在设置页手动运行单轮连通性测试，分别显示上传和删除耗时

连通性测试使用浏览器本地生成的 `360×280` 随机 PNG，通常约 300 KB，不包含论坛资料，也不会使用外部测试图片。16 图床、NodeImage 和填写了 User Hash 的 Catbox 会依次测试上传与凭据删除；ImgBB 测试图强制设置 60 秒自动过期，并明确标注 API Key 不能直接删除；FreeImage.host 因所用官方 API 不支持删除，会在上传前再次确认。测试清理失败或测试图无法 API 删除时，图片地址会写入“最近上传”供检查。

测试不再从图片直链重新下载文件：这一步容易受图床 CDN、防盗链或反自动化策略影响，而且测试者自己的下载网络不能代表其他查看者，可能长时间等待却得不到有参考价值的结论。

NodeImage 删除优先使用 API-Key 文档的 `/api/v1/delete/{id}`，并对现网页面及旧文档路径保留受控兼容。16 图床在“上传后立即删除”遇到 HTTP 404 时会短暂重试；仍失败则保留测试残留记录，并显示服务端响应摘要。

轮换只是把正常分享流量分散到多个已配置服务，不是规避图床规则或限流的保证。脚本不会自动并发测试、自动重试或在超时后故障转移，避免在用户不知情时制造多个公开副本。

## 🔐 隐私与第三方服务

### AI API Key

Key 通过 `GM_setValue` 保存在 Tampermonkey 脚本本地存储中。调用模型时，Key 只会发送到当前选择的 AI API：

- DeepSeek Key → DeepSeek API
- OpenAI Key → OpenAI API
- 第三方 OAI Key → 你自行配置的第三方 API

普通浏览 NodeSeek 页面不会把 Key 发送给论坛。

### NodeSeek 公开数据

画像与交易分析只使用脚本能够读取到的公开论坛信息。采样结果不是账号完整历史；没有出现在样本里的内容，不能解释为用户从未关注或参与。

生成中的任务状态和完成结果只保存在 Tampermonkey 本地；结果缓存有效期为 30 分钟，脚本在后续加载、读取或写入时清理过期记录。它们不会因为跨刷新恢复功能而上传到项目作者或 NodeSeek。

### 管理记录查询

管理记录使用第三方服务：

```text
https://api.xxboxx.de
```

首次查询前脚本会说明可能发送目标用户名、当前登录 NodeSeek 用户名与 UID，用于查询和限流。

### 图片托管

图片上传只会发送到分享窗口中明确选择的服务：16 图床、NodeImage、ImgBB、FreeImage.host 或 Catbox。上传意味着当前画像或交易报告图片会存储到相应第三方服务器。

凭据只保存在 Tampermonkey 本地，并仅在调用对应服务时发送。删除能力取决于服务公开 API：ImgBB 是删除网页，FreeImage.host 没有在本项目采用的官方删除 API，Catbox 匿名上传不可删除。

### 画像分享礼仪

公开可见不等于每个人都乐于被单独整理和再次传播。项目在分享窗口中提供简短提示，但不会代替使用者决定是否发布，也不会阻断正常分享。建议：

- 不把 AI 画像描述成官方结论、事实认证或人格定论
- 涉及负面判断时保留“仅基于公开样本”的上下文
- 对方明确表示不希望公开时，及时删除帖子中的图片链接
- 如果图片已上传图床，再按上传历史提供的能力删除远端文件；匿名或不支持删除的服务可能无法撤回
