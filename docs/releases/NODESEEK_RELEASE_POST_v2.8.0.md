# NodeSeek v2.8.0 发布帖

标题：`[开源/油猴] NodeSeek 用户 AI 画像 v2.8：刷新不丢任务、多图床轮换、管理记录与可调 Token`

正文：

这几天继续把 **NodeSeek 用户 AI 画像** 从 v2.7.1 往前推了一版，现在 **v2.8.0 已经在 GitHub 和 Greasy Fork 正式发布**。

这次不是单纯加几个设置项，主要解决的是我自己实际使用时最影响体验的几件事：

- 画像还在生成时回复帖子或刷新页面，任务会不会丢；
- 快速画像为什么看不到最近的管理记录；
- 只有一个图床时，连续分享是否容易把压力集中到同一家；
- 第三方 OAI 长上下文、高 reasoning 等两分钟，为什么会被过早判定超时；
- 一句话画像能不能更具体，少一点“正确但没什么用”的套话。

## 🪟 最大变化：回复、刷新或离开原页面，长任务不再直接丢失

这是 v2.8 最重要的底层改动。

我经常会先点贴主的 **AI画像**，然后趁模型还在跑，先写一段文字回复。以前只要提交回复触发页面刷新，尚未完成的画像状态就没了，只能重新点一次，再等几十秒，甚至可能重复消耗 Token。

现在开始画像或深度交易分析时，会同时创建一个小型临时任务窗口，由它承接长请求：

- 原 NodeSeek 页面可以提交回复、刷新、跳转或关闭；
- 回到页面后会重新连接原任务，恢复进度、终止入口和结果；
- 同一个临时窗口可以承接多个 UID，不会为每个用户弹一堆窗口；
- 全部任务结束后，临时窗口会自动关闭；
- 如果浏览器阻止弹窗，会退回当前页面执行，并在画像面板里说明本次刷新限制；
- 中断或超时不会自动重发模型请求，避免供应商已经生成却发生重复计费。

并发场景也补了专门修复：第一个用户还在跑时启动第二个用户，第二个任务不会再长期卡在“正在创建临时窗口”；尚未被临时窗口接收的任务也可以立即终止。

## ⚖️ 快速画像现在默认查询管理记录

以前管理记录主要放在深度交易分析里，但这会出现一个很实际的问题：

> 用户选择“近期活动”，快速画像看起来一切正常，却漏掉了这个账号最近刚被封禁或处罚的公开记录。

v2.8 给快速画像 / 自定义画像和深度交易分别增加了管理记录开关，默认开启。

管理记录会：

- 在模型调用前独立查询；
- 用 `M1`、`M2` 等证据编号送入 Prompt；
- 不论模型有没有主动提到，都在结果中确定性展示查询状态和详情；
- 即使主题 / 评论样本太少、没有调用模型，也不会把已经查到的管理记录藏掉；
- 查询失败、限流、关闭或取消会明确显示，不会伪装成“没有管理记录”。

同时，普通水贴或版规处罚不会只因为“有处罚”三个字就被自动写成交易风险；如果管理记录进入一句话画像，也必须明确写成“管理记录显示……”，不能装成模型从普通发言里推断出来的事实。

## 🧭 一句话画像继续收紧：少一点套话，多一点辨识度

v2.8 继续调整了快速画像 Prompt。

一句话画像会优先组合：

- 账号处于什么阶段；
- 主题与评论结构有没有明显反差；
- 哪些具体对象、商家、线路、产品或行为反复出现；
- 哪些是事实，哪些只是谨慎推断；
- 对应结论能否落到实际样本编号。

“新号”“零主题”“评论很多”这些特征不能单独被推导成“小号”或“刷等级”。AI 可以有观点，但不能为了显得犀利就硬扣帽子。

![快速 AI 画像结果](https://i.111666.best/image/B9YJia2Kul08yszz8KHsNq.png)

如果某个用户已经生成了深度交易报告、还没生成快速画像，再点击主 **AI画像** 按钮会优先打开已有深度结果，不会突然开始一次新的快速画像。真想补画像时，再从左下角明确选择生成即可。

## 🎚️ 三种模式分别设置 Token 上限和请求超时

不同账号的数据量差异很大：新号的画像可能只需要几千 Token，活跃老号的快速画像可能接近两万，深度交易分析则可能更高。

v2.8 不再让所有模式共用一个偏小的输出预算。每个 AI Provider 都能分别设置：

| 模式 | 默认最大输出 Token |
| --- | ---: |
| 快速画像 | 12,000 |
| 自定义画像 | 16,000 |
| 深度交易分析 | 32,000 |

可配置范围为 `2,000–65,536`。这里指输出 / completion 上限，也包含模型可能使用的 reasoning Token，不是输入加输出的总量。

请求超时也按三种模式独立配置。第三方 OpenAI-Compatible 默认放宽到：

- 快速画像：300 秒；
- 自定义画像：360 秒；
- 深度交易分析：600 秒。

这样对首字节较慢、长上下文或高 reasoning 的第三方服务会更宽容。结果里也会显示可观测的响应耗时，单次模型阶段超过两分钟会标注“本次较慢”，方便判断供应商线路和服务质量。

网络错误和超时不会自动重试，因为“本地没有收到结果”不等于供应商没有生成；自动重发可能产生第二份计费。只有模型明确因为输出预算耗尽而截断时，才最多扩容重试一次。

## 🤖 Model 改成常用下拉 + 其他手动输入

三个 Provider 现在都提供常用模型下拉框，同时保留“其他”手动输入：

- DeepSeek：`deepseek-v4-flash`、`deepseek-v4-pro`；
- OpenAI / 第三方 OAI：`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.6`、`gpt-5.5`；
- 第三方 OAI 的新安装默认模型改为 `gpt-5.6-sol`。

旧版本已经保存的 Model 不会被升级过程强制覆盖。

## ☁️ 从单一图床扩展到五家，并支持固定或均衡轮换

v2.8 现在支持：

- 16 图床；
- NodeImage；
- ImgBB；
- FreeImage.host；
- Catbox。

可以固定使用一家默认图床，也可以在已经配置好凭据的服务之间均衡随机轮换。轮换不是毫无规则地随机：每一轮每家最多出现一次，并尽量避免连续两次选中同一家。

这里有几个刻意的限制：

- 匿名 Catbox 不会自动加入轮换池；
- 分享窗口打开后，本次选定的 Provider 就固定，重试不会偷偷换一家；
- 上传超时不会自动故障转移，因为第一家可能已经收到图片，自动换图床可能制造多个公开副本；
- 所有 Token / API Key 都要用户自行申请，插件不内置开发者 Key。

![图片分享菜单](https://i.111666.best/image/vvCFACjZZDO6h890zVIEAK.png)

图床设置里也增加了单轮连通性测试：浏览器本地生成一张约 300 KB、不含论坛内容的随机 PNG，分别显示上传和删除耗时。测试不会再重新下载图片直链，因为本地下载速度既不能代表其他用户，也容易被 CDN、防盗链或反自动化策略拖住。

删除能力会按服务真实情况区分：

- 16 图床、NodeImage：使用相应凭据调用 API 删除；
- Catbox：绑定 User Hash 的上传可以删除，匿名上传不行；
- ImgBB：打开服务返回的删除页；
- FreeImage.host：当前采用的官方 API 不提供插件内远端删除。

本次发布前，16 图床和 NodeImage 的上传 / 删除测试均已实际通过；其中 NodeImage 还兼容了官方接口路径版本漂移，16 图床则保留完整删除地址并处理上传后立即删除的短暂 404。

## 🔍 深度交易分析仍然是“整理证据”，不是替你决定能不能交易

深度模式会扩大公开历史采样，重点整理交易主题、帖子正文、第三方公开回复、买后测试、后续反馈、可能的交易行为链和管理记录。

![深度交易分析结果](https://i.111666.best/image/cntUnxH06ENHwrIFsUfGQr.png)

它无法验证：

- 现实身份；
- 私聊内容；
- 实际付款和交付；
- 当前账号是否仍由原持有人控制；
- 没被采样到的全部历史。

所以老号不代表绝对安全，Lv1 也不代表一定危险，高等级更不是官方信用担保。涉及较大金额时，仍然应该结合中介、账号历史、交易上下文和自己的判断。

## 🔐 关于分享和隐私

画像整理的都是公开论坛信息，但“公开可见”不代表每个人都乐于被集中总结并再次传播。

插件不会因此加一个强制确认框阻断正常分享——分享本来就是社区交流和项目传播的重要方式。不过，如果被画像者明确表示不希望继续公开，建议及时移除帖子里的图片，并根据上传历史显示的能力删除图床远端副本。

也请尽量不要把 AI 输出写成官方结论、事实认证或人格定论，特别是涉及负面判断时，保留“仅基于公开样本”的上下文。
